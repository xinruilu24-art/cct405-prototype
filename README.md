# Prove It, Picasso!

CCT405 游戏原型。

可玩的 HTML 原型。在线试玩：https://xinruilu24-art.github.io/cct405-prototype/

本地试玩：下载 index.html，用浏览器打开。

剧本管理器：[在线编辑](https://xinruilu24-art.github.io/cct405-prototype/script-manager.html)。首次在线打开会载入已发布的剧本；已有浏览器数据会保留，不会自动覆盖。

若只看到旧稿、帖子为 0 或内容不完整，刷新管理器，点击顶部提示中的「载入已发布剧本」，再选择「导出本机备份并载入」。公开仓库的剧本读取不需要 Token；提交修改仍需要 Token。本机与线上版本不同时会显示提示，网络错误也会给出原因，不会悄悄覆盖本机编辑。

发布更新：先在「GitHub 设置」中填写自己的 Token，保持 owner 为 xinruilu24-art、repo 为 cct405-prototype、分支为 main、路径为 data/script.json。编辑后点击「提交并发布」，确认提交说明即可直接提交并推送，不需要另做 push。有效文本会自动编译；语法错误会阻止提交，并给出事件和行号。远程版本变化时仍须处理冲突。GitHub Pages 发布完成后刷新游戏，新开的一局会读取最新 JSON；正在进行的局保持原版本。Token 仅在当前浏览器设置中，不进入备份或提交文件。

角色管理：先切换画师 Case，再进入左侧「角色管理」。可以新增、修改名称、英文 key、别名和备注；下方可查看引用它的 block 并跳转。改名保留旧名为别名，台词可以使用名称、key 或别名；改名不会替换台词正文里提及的人名。仍被引用的角色不能删除。角色随所属 Case 一起复制、导入、导出和同步，副本独立保存。

同步范围：现有游戏入口的帖子、评论、聊天文案、选项标签、Action 数值和画师偏好通过发布包读取。额外新增聊天、选项或剧情跳转不会自动创建新的游戏入口，仍需接入游戏流程；发布时会列出未绑定的自建聊天 block。已有示例旧稿保留在管理器里，未修改的示例不作为新剧情发布。本地双击 index.html 使用随 HTML 保存的剧本版本；要使用后续发布的最新数据，请打开网页版游戏。

Token 权限：优先使用仅授权本仓库、Contents → Read and write 的 fine-grained token。若当前账号是他人个人仓库的协作者、无法选中该仓库，可检查仓库授权或使用带 public_repo 权限的 classic token。[GitHub 官方说明](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)。

新手指引：点手机屏幕逐条阅读 Chloe 消息，再从手机主界面开始浮窗导览。浮窗紧邻当前操作或指标，玩家逐个点击高亮的真实操作位置；练习不会实施行动，也不会改变时间、余额、舆论、压力或证据。效果以文字描述，包含收藏证据和公告。导览结束后回到 Chloe 聊天，由她作结，再交给玩家自行探索。可以跳过，也可从 Chloe 聊天或设置中重看。

收藏证据：可收藏材料和正式发布的对赌公告，点击帖子底部星星进入证据清单，不消耗行动点。截图功能已删除。配置说明见 [EVIDENCE_COLLECTION.md](EVIDENCE_COLLECTION.md)，公告改编说明见 [LIVESTREAM_RULES_SOURCE.md](LIVESTREAM_RULES_SOURCE.md)。

画师聊天：点手机屏幕逐条展开回复和文件，读完后再推进时段及播放转场。评论回复等非聊天行动短暂展示结果后自动转场，无需再点一次。

过程视频：在画师的 MiChat 聊天中提出制作请求，读完她对耗时的说明后选择同意或暂时不做。同意后制作发布，展示完回复后消耗两个时段；拒绝不会发布，也不消耗时段。

所有玩家 Action 的结算时机：在对应聊天或流程 block 中移动原有 `@action: 英文key`。指令前的消息先读完，执行到指令时应用该 Action 的数值和时段消耗，转场后继续指令后的消息、文件和帖子。外卖的餐费、对赌压力、评论舆论等也在各自指令处结算；原有免费操作仍是 0 时段。不要为移动结算时机复制指令，否则会执行两次。Action 的消耗量与效果在共用 Action 管理中编辑；本 Case 的画师偏好继续叠加。

例如在 `chat.video` 确认分支里，把已有 `@action: approve_video` 移到“开始制作”的回复之后、“视频已完成”的回复之前，就会先消耗两个时段再显示完成回复。陪伴使用 `chat.care.*`、外卖使用 `chat.food`、转发使用 `chat.forward.*`、对赌使用 `chat.wager`、评论使用 `system.comment-reply`、公开回应使用 `system.respond`。没有原聊天的操作可在「流程 / 结局」的“操作时序” block（`action.rest`、`action.collect_evidence`、点赞／点踩和 `action.stream_start`）中编辑。同一套规则覆盖两个 Case，副本各自保存。已有直播三轮仍按游戏轮次衔接；普通时间耗尽后先读完当前段落，再进入投票。

直播对赌：从画师聊天提出，先阅读压力说明再确认；确认使画师 1 压力 +20、画师 2 +30。她回复将直播约在第五天，读完后发布规则公告，再消耗一个行动点。拒绝不增加压力或扣点。画师 1 至少保有 ¥50，画师 2 至少保有 ¥80。发起和开播前均检查资格；当前规则检查余额，不另扣保证金。

普通支持评论回复使舆论 +2；转发帖子及点外卖各消耗一个行动点。转发先读完画师回复再推进时段。

评论与直播的证据判定：切换画师 Case，打开帖子 block，在右侧预览中找到要设置的评论，展开“回应判定”，勾选“启用本条证据判定”，再逐项勾选能回应这条内容的材料。楼中楼逐条独立设置，不继承上一层名单。直播请打开 Day 5 的“第五天直播 · 弹幕 1／2／3”，在相同位置设置弹幕立场与相关证据。勾选会立即写回文本、保存并编译；完成后点击顶部“提交并发布”，游戏新开一局读取新配置。

普通评论：相关证据 +10、无关证据 −5、无证据 −5；感谢支持仍为 +2。直播：相关证据 +20、无关证据 −10、无证据 −10；同意支持弹幕 +5、同意质疑 −5、中立或未分类为 0。数值仍从共用 Action 与当前 Case 的偏好读取，可以继续编辑，不在游戏里显示具体分值。新增的共用 Action 为 `rebut_irrelevant_evidence`、`live_rebut_irrelevant_evidence` 和 `live_agree_accuse`。

证据名单由作者逐条设置，初始不代填。未设置时，出示证据不会因相关性加减舆论（无证据反驳仍按上述规则扣除）；启用但没有勾选材料时，所有证据均按无关处理。普通回复仍消耗一个时段，直播回复保持原来的 0 时段，并在剧本中原有 `@action` 的位置结算，既有额外 `@effect` 仍会叠加。

错误证据后的楼中楼：仅当当前评论已启用证据判定、所选材料不在相关名单时，由原评论者在玩家回复下方追加“这完全是 bs。”；同一条不会重复追加，离开帖子再回来仍保留。直播同样显示原观众的回复，点击“继续”后进入下一条弹幕或投票，最后一轮也会先展示回复。这条跟帖不再额外扣时段或舆论。每个 Case 的默认回复文案可在「流程 / 结局 → 无关证据 · 评论者的楼中楼回复」（`system.irrelevant-evidence-reply`）中单独编辑。

文本写法：在对应 `[comment 实际评论ID]` 内写 `relevant_evidence: e1, e3`；直播则写在 block 头部，并用 `stance: support`、`accuse` 或 `neutral` 表示立场。`relevant_evidence: none` 表示全部无关，删除这一行表示停用判定。证据 ID 来自当前 Case 引用表；未知或重复 ID 会提示行号。名单、立场、评论 ID 与 Case 归属随 JSON 备份、导入、复制 Case 和 GitHub 发布保存。布丁材料及青柠记录的原有用途与说明保持不变。


验证：`node --test tests/*.test.cjs`。

咪画师消息：客户聊天底部可以回复。客户布丁第二天出现，索取后会逐条发来说明和两次约稿过程记录；读到材料时自动加入证据清单，可用于回应和直播。小葵可提供已有订单时间线，青柠可提供订单核对记录。阅读和这类取证回复不消耗行动点，重复打开不会重复领取。教程使用独立预览，不会提前解锁客户或发送消息。

第三天事件：第三天早上，指控方发布新的鉴定帖（n5），舆论 -20、画师压力 +10，仅触发一次。自动打开画师聊天显示提醒，点手机展开新帖子卡片，点卡片进入正文；帖子同时置于小粉书信息流首位，可以按原有规则回应评论或转发。阅读提醒、打开帖子不会额外扣行动点或重复结算事件。
